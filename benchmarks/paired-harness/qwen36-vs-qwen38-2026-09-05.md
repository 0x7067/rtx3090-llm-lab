# Qwen3.6 Heretic/MTP versus Qwen3.8: RTX 3090

The fixed 4,096-token quality budget produced **53/54** full-score answers for Qwen3.8 and **43/54** for Qwen3.6. Both completed all 58 HTTP requests, including four performance probes. These are single-run measurements of the configured serving profiles on 2026-09-05.

## Profiles and protocol

| Setting | Qwen3.8 control | Qwen3.6 candidate |
| --- | --- | --- |
| Model | Qwen3.8-27B UD-Q4_K_XL-v3 | llmfan46 Qwen3.6-35B-A3B uncensored Heretic Native-MTP-Preserved Q4_K_S |
| Speculation | Q4_K_M DFlash2, depth 7, plus ngram-mod | Embedded MTP, depth 3 |
| KV and context | q4_0, 131072 shared tokens, two slots | q8_0, 131072 tokens, one slot |
| Runtime | llama.cpp cuda-swap-v18 | Same image |

This compares two deployed profiles with different architecture, fine-tuning, weight precision, KV precision, and speculation. It does not isolate the model-version or inference-engine effect. The Qwen3.6 result is for the configured **35B-A3B Heretic** model; stock Qwen3.6-27B was not tested.

Both arms received the same frozen messages, tool definitions, seed 42, temperature 0, top_p 1, medium reasoning request, and output budgets. Quality had a 4096-token cap; decode probes had 512, and prefill probes had one. There was one observation per case and one seed. Actual template/token counts can differ by profile. Runs were sequential on the same RTX 3090; Qwen3.6 ran first, its separate diagnostic followed, then Qwen3.8. Warmup and model loading are excluded. The endpoint was shared, cache state was not administratively reset, and cached-token observations are retained in JSON.

## Fixed-budget quality

| --- | ---: | ---: | ---: |
| transcript_qa | 2/2 | 2/2 | 2 |

| retrieval | 6/6 | 6/6 | 2 |
| coding | 20/20 | 10/20 | 20 |

| extraction | 6/6 | 5/6 | 5 |
| relevance | 1/2 | 2/2 | 2 |

Nine Qwen3.6 coding answers exhausted 4096 tokens in reasoning before emitting a final answer. The completed byte-batching implementation returned early on empty input and failed the required `max_bytes >= 1` validation. The escaped-text extraction used `text` instead of the requested `value` key. These remain failures in the primary denominator.

Qwen3.8's remaining relevance answer returned only document A, omitting relevant
document C, for **2/3 F1**. Its result is therefore 53 full scores plus one
partial score, rather than 53 passes and a zero. This paired campaign has new
request nonces; the earlier 54/54 single-arm baseline remains a separate run.

The suite is authored synthetic regression data, including reused smoke support cases. Related tool steps and retrieval depths share clusters. Bootstrap intervals are exploratory, not multiplicity-adjusted, and are not a proof of general model quality. The JSON contains every per-tier interval and verdict; degenerate constant-difference bootstraps stay inconclusive.

## Larger-budget diagnostic

Qwen3.6 reran only its nine capped coding cases at **8192 tokens**. **7/9 passed**. The rate-limiter and dictionary-diff cases still exhausted the larger budget. Request-body comparison verified that only `max_tokens` changed, including identical prompt nonces. This post-hoc, Qwen3.6-only diagnostic does not replace the paired scores, and cache reuse makes its latency unsuitable for the main comparison.
