What was held constant

Same target weights, INT8 output head, chat template, sampling and GPU power profile. Both configured 200K context and four request slots, with 12 CPUs, a 36 GiB memory cap and 24 GiB shared memory.

Production used DFlash2-7 and a 16 GiB CPU prefix cache. SparseKV used MTP-7, FA2 prefill and an INT4 host tier. This compares the complete configurations, not just sparse attention.

How to use this result

SparseKV merits further qualification for long, concurrent conversations. Keep the current default while evaluating that use case: this screen did not test four clients, 250K contexts, images, cancellation or long coding quality.

The first candidate startup hit kubelet image garbage collection. Production was restored, the exact images were temporarily retained for the retry, and their original retention labels were restored afterward. No production model or host policy was changed.
